# Internal API contract (Phase 2)

## Sandbox runner (HTTP, default 127.0.0.1:8090, header `X-Session-Id` on every call)
All paths are absolute inside the workspace root (`DOT_WORKSPACE`); anything resolving outside (symlinks, `..`) -> 403.
Errors: JSON `{"error": "<snake_code>", "detail": "<text>"}` with proper HTTP status.
- `GET  /health`
- `POST /fs/read`  `{path, offset=0, limit=2000}` -> `{content, total_lines, numbered: true}` (content `cat -n` style `"%6d\t"`; marks file as read for the session)
- `POST /fs/write` `{path, content}` -> `{path, created: bool}`; overwriting an existing file not read this session (or changed on disk since read) -> 409 `read_required`
- `POST /fs/edit`  `{path, old, new, replace_all=false}` -> `{path, replacements, lint: str|null}`; same read rule; `old` not found -> 422 `no_match`; multiple matches without replace_all -> 422 `ambiguous`; post-edit lint (ruff for .py, `bash -n` for .sh, `node --check` for .js when available) returns text in `lint`, never fails the edit
- `POST /fs/glob`  `{pattern, path=null}` -> `{paths: [..]}` sorted by mtime desc, max 500
- `POST /fs/grep`  `{pattern, path=null, glob=null, output_mode="files_with_matches"|"content"|"count", context=0, ignore_case=false, head_limit=250}` -> `{output: str}` (uses rg when present, else python fallback)
- `POST /exec`     `{command, timeout_s=120, cwd=null, background=false, stdin=null}` -> `{stdout, stderr, exit_code, timed_out, truncated, spill_path|null, shell_id|null}`; output over 30000 chars is spilled to `<workspace>/.dot/tool_outputs/<id>.log` and truncated head+tail in the response
- `POST /exec/output` `{shell_id}` -> `{stdout, stderr, running, exit_code}`; `POST /exec/kill` `{shell_id}`

## Backend public API (all under `/v1`, bearer token, `protected_router`)
- `POST /v1/sessions` `{mode?}` -> `SessionInfo`
- `GET  /v1/sessions/{id}/messages` -> `list[Message]`
- `POST /v1/sessions/{id}/mode` `{mode}` -> `SessionInfo`
- `POST /v1/sessions/{id}/chat` `{message}` -> `text/event-stream`; each `data:` line is one JSON `StreamEvent` from `dot_contracts.events`; stream ends after a `done` event. One turn at a time per session (else 2001).
- `POST /v1/approvals/{approval_id}/resolve` `{decision: "allow"|"always"|"reject"}` -> `{ok: true}`; unresolved approvals time out after 300 s (3001).
- `POST /v1/sessions/{id}/stop` cancels the running turn.

## Backend implementation notes (Phase 2)
- Auth: `Authorization: Bearer <DOT_API_TOKEN>`; errors are the list envelope (`code` 2001 busy, 2000 no session, 3003 unknown approval).
- `POST /v1/sessions` -> 201 `SessionInfo {id, mode, title, created_at}`; `GET /v1/sessions` lists recent; title is taken from the first message.
- SSE: `Content-Type: text/event-stream`, frames are `data: <json>\n\n`, no `event:` or `id:` lines, no keep-alives. Stream always ends with exactly one `done` event, preceded by an `error` event on failure.
- Event order per model step: `token` (thinking=true for reasoning) ..., `usage`, then `tool_call` for every call, then per call (in order) optional `approval_required`, then `tool_result`. Parallel read-only calls emit their results together after all finish.
- `done.stop_reason`: `end_turn`, `max_iterations`, `cancelled` (stop endpoint or client disconnect), `error`, `approval_timeout` (preceded by `error` code 3001).
- Error codes in `error` events: 4000 llm down, 4001 sandbox down, 4003 malformed tool calls twice, 3001 approval timeout, 1000 internal.
- Plan-mode and rejected calls are not errors on the stream: they arrive as `tool_result` with `is_error=true` and text starting `Denied (error 3000)`.
- `POST /v1/sessions/{id}/stop` -> `{ok: true, stopped: bool}`. `approval_required.diff` is set for Edit only (`- old` / `+ new` lines).
- `/ready` checks DB, sandbox `/health`, llama `/health` (503 code 1008). Tool results over 3000 chars (Read: 20000) are head/tail summarised.
- Permissions: tools are mutating unless they declare `mutating=False` (fail closed). Plan mode denies every mutating tool before any rule is read, and again after an approval if the mode changed meanwhile. "Always" for Bash is scoped to the exact command string for the session.
- Tool-call ids are made unique per transcript by the engine; stored `arguments` is always valid JSON. Every announced call gets exactly one `tool_result` event, including malformed ones. Tool output has control tags (`<system-reminder>`, `<tool_call>`, `<think>`) neutralised.
- Sandbox: fs write/edit into `<workspace>/.dot/` is refused (403 `protected_path`); non-regular files are refused on read; shells run with a 1 GiB file-size ulimit and the whole process group is killed when the command ends; the runner process is non-dumpable so shells cannot read its environ.

## Skills (Phase 3)
- `GET /v1/skills` -> `[{name, description, source: workspace|user|bundled, available, reason, model_invocable}]`; `GET /v1/skills/{name}` adds `license, allowed_tools, requires, body, files` (404 code 1002 when unknown).
- Workspace-tier skill output is tainted (Stage B) and `/name` for a workspace skill does not inline the body: it asks the model to load it with the Skill tool. Skill files are read with a per-skill jail (a symlinked skill directory is its own root; links leaving it are refused), size caps, and YAML aliases are rejected.
- Tiers: `<workspace>/.dot/skills` > `~/.dot/skills` (`DOT_USER_SKILLS_DIR`) > bundled `skills/` (`DOT_SKILLS_DIR`). Unavailable skills are listed with the missing tool/MCP/binary in `reason`.
- Per turn the top 3 BM25 matches go into the frozen reminder; the `Skill` tool (`name, args?, file?`) loads the body or a bundled file (jailed to the skill dir). A chat message starting `/name args` is stored expanded with the skill body; unknown names pass through.

## Phase 3: governance
Sandbox (internal, backend-only, same jail and `protected_path` rules, `X-Session-Id` required, id must match `[A-Za-z0-9_-]{1,64}`):
- `/exec` takes an optional `stdin` string (max 1 MB), piped to the command then closed; `null` keeps stdin at /dev/null.
- `POST /internal/checkpoint` `{path}` -> `{checkpoint_id, existed}`: stores the current content (or a "did not exist" marker) in `<workspace>/.dot/checkpoints/<session>/<n>/{meta.json,content}`; `n` increases per session.
- `POST /internal/restore` `{checkpoint_id, dry_run?}` (dry_run only proves the snapshot is intact) -> `{path, action: "restored"|"deleted"}`.
- `POST /internal/realpath` `{path}` -> `{path, inside}`: symlinks resolved; the backend judges Read/Write/Edit/Grep/Glob rules on both the given and the real path (deny on either).
- `POST /internal/binaries` `{names}` -> `{found}`: which executables exist on the sandbox PATH; skill `requires.binaries` are checked here (cached 60 s), not on the backend host. If the sandbox is unreachable, binary-requiring skills are listed unavailable.
- `POST /internal/peek` `{path}` -> `{exists, content|null}` (null for binary or >1 MB). Does NOT mark the file as read.

Settings: `~/.dot/settings.json` (user) and `<workspace>/.dot/settings.json`, plus the baseline `deploy/config/dot/default_permissions.json` (`DOT_DEFAULT_PERMISSIONS_PATH`). Lists are unioned (workspace first, then user, then baseline); a rule can never be removed by a lower layer. Precedence deny > allow > ask. Invalid files fail closed (error 3005), and so does a missing baseline file. Shell rules also see `sudo`/`env`/`xargs`/`bash -c`/`find -exec`/`git -c`/inline `python -c` runs, `<` redirects, globs and `ref:path` arguments; deny/ask only ever tighten through those views, allow rules match the outer command. These rules are lexical guardrails; the sandbox is the boundary. In compose, `.dot/settings.json` and `.dot/hooks` are mounted read-only into the sandbox (`make init` creates them) and the workspace is mounted read-only into the backend.
`{"permissions": {"allow": [], "ask": [], "deny": []}, "hooks": {"<Event>": [{"matcher": "*", "command": "...", "timeout": 30}]}}`
- Rules: `Tool`, `Tool(specifier)`. Bash specifiers: `git status:*` (prefix at a word boundary), `npm run build` (exact), `git * --help` (glob). A command is split on `&& || ; | & newline` and substitutions; allow needs every segment to match (a segment with `$(...)`, backticks, `$VAR`, an env prefix or a redirect outside /dev/null never matches an allow rule), deny/ask match on any segment. `Read(...)` rules also cover Grep/Glob and shell readers (`cat`, `head`, ...), `Edit(...)` rules cover Write and shell writers/redirects. Path specifiers are gitignore-style globs (`./secrets/**`, `**/.env`, `*.pem`, `~/.ssh/**`, `/abs/**`), matched on the normalised path.
- Hook events: SessionStart (first message of a session), UserPromptSubmit (exit 2 blocks the turn: `error` 3006 then `done` `blocked`), PreToolUse, PostToolUse, Notification (approval needed), Stop (exit 2 sends stderr back to the model, once per turn), SubagentStop and PreCompact (engine support only, fired by later phases via `Governance.fire`). Commands run in the sandbox with JSON on stdin (`hook_event_name, session_id, cwd, tool_name, tool_input, tool_response, prompt`). Exit 0 ok (stdout may be `{"decision": "block"|"ask"|"allow", "reason", "updatedInput"}`), exit 2 blocks (stderr -> the model as an error tool_result), other codes and timeouts are non-blocking warnings. A hook can block, rewrite arguments (rules and mode are re-evaluated on the rewrite) or force an approval; `allow` is ignored, so a hook never loosens a deny rule, plan mode or an approval.
- Pipeline per call: rules -> PreToolUse hooks -> mode -> classifier (auto only) -> user. Deny rules and plan mode end the call before hooks run.

Auto mode: Stage A (bashlex, deterministic) returns allow/ask/deny; Stage B is taint tracking over `ToolResult.tainted` text (an argument sharing a >=12 char substring with it, or any mutating call after tainted input with no user turn, escalates). Allow only when both are clean. `deny` is final (tool_result `Denied (error 3000)`), `ask` becomes an approval card with `approval_required.verdict = {decision, stage, reason}`. Parse failures escalate.

Backend:
- `POST /v1/sessions/{id}/rewind` `{to_seq}` -> `{kept_through_seq, rewound_messages, restored: [{path, action}]}`. `to_seq` is any message seq; the turn containing it is kept whole and everything after it is rewound (`0` rewinds everything; to undo prompt N, pass any seq of the previous turn). Files changed by later Write/Edit calls are restored newest-first from their checkpoints; later messages get `rewound=true` (rows are never deleted). While a turn runs: 2001. Unknown target: 2002. Every checkpoint is verified (dry run) before any file is touched, so a missing/pruned one fails the whole rewind with 3004 and changes nothing. A Write/Edit whose checkpoint cannot be taken is not executed.
- `GET /v1/sessions/{id}/messages?include_rewound=1` includes rewound rows (`Message.rewound`); default excludes them, and they are excluded from model context.
- `GET /v1/audit?session=&limit=50&cursor=` -> `{items: [{id, session, mode, tool, args, decision, source, reason, created_at}], next_cursor}` newest first, limit 1..200. Append-only table (SQLite triggers reject UPDATE/DELETE); one row per evaluated call plus one `source=user` row per human answer. `source` is rule | mode | hook | classifier | user.
- `approval_required.diff` is now set for Write too (unified diff against the current file, `--- /dev/null` for new files); Edit keeps the `- old` / `+ new` format.
- New codes: 2002 rewind target invalid, 3004 restore failed, 3005 settings invalid, 3006 prompt blocked by hook, 3007 checkpoint failed.

## Phase 4: agent tools
New `StreamEvent` types (all additive; clients must ignore unknown `type`):
- `question` `{question_id, question, options: [{label, description}], multi_select}`: emitted by `AskUserQuestion` right after its `tool_call`; the call blocks until answered. 2-4 options, the user may always type free text instead.
- `subagent` `{label, subagent_type, status: queued|started|step|finished, detail}`: progress of an `Agent` call (`step.detail` = tool name, `finished.detail` = ok|error|cancelled). `label` is `"<type> <n>"` (n counts per session). Nested subagents report through their parent, same stream.
- `approval_required` gained `subagent: str|null` (label of the subagent that is asking; null for the main agent). `ExitPlanMode` approvals carry the plan markdown in `diff`.
- Endpoints: `POST /v1/questions/{id}/answer` `{selected: [label...], other: str|null}` -> `{ok: true}` (2003 unknown/answered, 2005 labels not in options, more than one label for single select, or empty answer; unanswered after 300 s `DOT_QUESTION_TIMEOUT_S` -> the tool returns an error result, the turn goes on, code 2004 internal). `GET /v1/sessions/{id}/tasks` -> `[TaskInfo {id, subject, description, status, blocked_by, created_at, updated_at}]` (`dot_contracts.tasks`).
- Error codes: 2003 question not found, 2004 question timed out, 2005 answer invalid, 4004 task not found.
- A stopped turn closes open `Agent` / `AskUserQuestion` calls in the transcript (`Cancelled by the user.`); the stream itself ends with `done: cancelled` without extra `tool_result` events (same as approvals).

Deferred tools and `ToolSearch`:
- `ToolDefinition.deferred=true` tools are not in the static system prompt nor in the `tools` array. The per-turn reminder lists them: `Deferred tools available via ToolSearch: a, b`.
- `ToolSearch(query, max_results=5)`: BM25 over name (weighted x3) + description, or `select:A,B` for exact names. Matches are activated for the session and their schemas come back in the tool result. A deferred tool called before activation returns an error telling the model to call ToolSearch first. Activation lives in memory (lost on restart; the model just searches again).
- Cache implication (measured in `tests/agent_tools/test_tool_search.py`): llama-server renders `tools` into the prompt before the messages and builds tool-call grammars from that array, so an activated tool has to be in it. The array only ever grows by appending at the end, in activation order. Result: the system prompt and every old schema stay byte-identical (cached), the history after the tools block is re-prefilled once at the next call after an activation, then cached again. Activating a tool is therefore not free on a slow GPU; prefer one `select:` with all needed names over several searches.
- No deferred tool ships yet (Memory, Cron, Browser, NotebookEdit, MCP are later phases); the mechanism is exercised with test tools.

Tasks: `TaskCreate(subject, description?, blocked_by?)`, `TaskUpdate(task_id, status?, subject?, description?, blocked_by?)` (`blocked_by` replaces the list), `TaskList`, `TaskGet(task_id)`. Public ids start with `T`. SQLite only (the sandbox protects `.dot`, so no `tasks_dag.json`). Cycles, unknown blockers and starting or completing a task with open blockers return an error text, never a crash. Subagents share the root session's tasks. Writes are serialised (parallel `TaskUpdate` calls cannot jointly create a cycle); max 200 tasks per session; the reminder text of a task subject has control tags neutralised. The open tasks are appended to the per-turn reminder (frozen at write time like everything else in it); `backend.cognition.services.tasks.summary.open_tasks_summary(session_id)` (async, returns "" when none) is for compaction.

Plan mode: `EnterPlanMode` switches the session mode to `plan` (the previous mode is remembered in memory and forgotten when the user changes the mode through `POST /v1/sessions/{id}/mode`; default after a restart or when the user set plan mode) and writes an audit row (`source=mode`, reason `session mode changed X -> plan`). `ExitPlanMode(plan)` needs a human approval (`approval_required` with `diff` = plan, `/v1/approvals/{id}/resolve`); allow/always restores the previous mode and stores the plan as a message with `role: "plan"` (visible in `/messages`, never sent to the model). Reject or the 300 s timeout leaves plan mode on and returns an error result. Both tools are read-only for governance and go through rules/hooks/audit like any tool.

Subagents: `Agent(description, prompt, subagent_type?)`, type default `general-purpose`.
- Types: `Explore` and `Plan` (Read, Glob, Grep, WebSearch/WebFetch/Skill when present; read-only, may run in parallel), `Verifier` (the same plus Bash/BashOutput/KillShell, normal approvals), `general-purpose` (every non-deferred tool except ToolSearch, AskUserQuestion, EnterPlanMode, ExitPlanMode; it may use `Agent` itself). Tools outside a type are simply absent (`Unknown tool`). Max nesting depth 2, then the call returns an error text.
- Each run is a child ReAct loop (own short system prompt, fresh in-memory context, 15 model calls max) with the same Governance, ToolRunner, audit, taint and sandbox. The parent's current mode applies to the child (plan mode binds it). Hooks `SubagentStop` fire via `Governance.fire` after the run; exit 2 appends its stderr to the report.
- Child session id is `<parent>-sub-<n>` (the sandbox only accepts `[A-Za-z0-9_-]`, so not `:sub:`). Taint, audit rows (`GET /v1/audit?session=<child id>`) and sandbox read tracking (a child must `Read` before it edits) use the child id; "always allow", tasks and checkpoints belong to the root session, so child edits are rewindable. A tainted parent makes the child start tainted; the report is `tainted` when the child consumed untrusted content.
- Concurrency: a semaphore of `DOT_LLM_PARALLEL_SLOTS` (default 2) bounds running subagents; extra ones wait (`queued`). Runs started from a subagent (depth 1, they are leaves because of the depth limit) use a separate semaphore of the same size, so a child holding the only slot can never wait on its own children. Parallel `Agent` calls in one message run concurrently only for Explore and Plan; others run in order. Stopping the turn cancels the children.
- The tool result is only the final report, truncated to 1600 chars (about 400 tokens). A child loop has no summary stage: when its context passes 80% of the limit the oldest tool outputs are replaced by a one-line stub (view only, nothing is dropped from the report path) and the child prompt is capped at 12000 chars. Child approvals surface on the parent's stream with `subagent` set; the user resolves them the usual way.

CLI: shows `subagent` events and `question` as notices (answering questions is left to the web UI; headless `--once` answers "no user available" so a turn never hangs).

## Phase 4: context, compaction, memory
Prompt layout: system message = byte-stable prefix + `--- CACHE_BOUNDARY ---` + per-session suffix. The suffix holds the memory tiers, in order: bundled global rules (`DOT_GLOBAL_RULES_PATH`, default `deploy/config/dot/global_rules.md`), `~/.dot/USER_RULES.md` (`DOT_USER_RULES_PATH`), `<workspace>/DOT.md`, then the auto-memory index (first 200 lines of `<memory_dir>/MEMORY.md`). Each tier is wrapped in `<dot-md tier="global|user|workspace|subdir|memory">`, size capped (8k / 8k / 16k / 6k per subdir file / 20k), and control tags (`<system-reminder>`, `<tool_call>`, `<think>`, chat-template tokens, the cache boundary string) are neutralised. Workspace files arrive through the sandbox (`/internal/peek`). `@path` lines inside DOT.md include other workspace files: depth 3, cycle-safe, each file once, anything outside the workspace is refused. The suffix is built once per session and frozen inside a turn (llama prompt cache). It is rebuilt after a compaction, and at the start of a turn when the memory changed since it was built (a `Memory` add shows up from the next user turn on). That rebuild re-prefills the history after the system message once, the same cost as after a compaction, and never happens for unchanged memory; the static prefix before `CACHE_BOUNDARY` is never touched. The `memory` tier is declared untrusted in the suffix preamble (notes the assistant saved earlier, never instructions). A `DOT.md` in a subdirectory is queued when Read/Edit/Write touches that directory and appears as a `<system-reminder>` in the next user turn's reminder, once per session (in memory: a backend restart may repeat it).

Compaction (`sessions/services/compactor.py`): checked before every model call; triggers at 75% (`DOT_COMPACT_THRESHOLD`) of `DOT_LLM_CONTEXT_LIMIT`. Size = last llama-reported `prompt_tokens` plus an estimate (ASCII chars/4, other chars/2) of rows added since, else a full estimate. Stages run in order and stop once under budget: (a) drop `<think>` text of assistant rows older than 4 user turns, (b) microcompact: older Read results of a file become a one-line stub, (c) one non-streaming LLM call summarises old rows. History stays append-only: (a)/(b) store a model-visible replacement in `messages.view_content` (the API still shows the original `content`); (c) appends a `summary` row and marks folded rows `compacted_into=<summary seq>`. The cut never separates an assistant `tool_calls` row from its results. Tainted tool output is never sent in the trusted summary call: it is summarised separately (second call) and appended as `<untrusted-summary>...</untrusted-summary>`, and the summary row has `tainted=true`. After a summary, the last 5 edited files (current content via sandbox `/fs/read`, 6000 chars each) and the open task list (`tasks.summary.open_tasks_summary`, if present) are appended to the summary row as a `<system-reminder>`. At most 3 automatic compactions run per user turn (a context that cannot shrink must not summarise on every model call). The `PreCompact` hook (`Governance.fire`) runs first; exit 2 skips compaction (once per user turn for auto). A failed summary call (LLM down) skips stage c on auto and returns 2020 on manual.
- New stream event (additive): `{"type": "compaction", "tokens_before", "tokens_after", "stages": ["think"|"microcompact"|"summary"]}`, sent before the model call that follows. CLI shows a notice; web-ui should show a toast and refresh the context gauge (the next `usage` event carries the new size).
- `POST /v1/sessions/{id}/compact` -> `{compacted, reason|null, tokens_before, tokens_after, stages}`; folds everything except the newest message. 2001 while a turn runs; 2020 if the summary call fails; `reason` is `blocked` (PreCompact hook) or `nothing to compact`.
- `GET /v1/sessions/{id}/messages?include_compacted=1` includes folded rows (`Message.compacted`, `Message.tainted`; `role: "summary"` rows are shown by default, at their append position). Order is by seq; the model sees the summary first.
- `GET /v1/sessions/{id}/context` -> `{limit, threshold, used, source: reported|estimated, tiers: {prefix, global, user, workspace, memory}, messages: {user, assistant, tool, summary}, compactions: [{id, trigger: auto|manual, stages, tokens_before, tokens_after, summary_seq, undone, created_at}]}` (token counts are estimates except `used` when reported).
- Rewind and compaction: a rewind that goes back past a compaction un-compacts. The summary row is rewound with the rest (rows are never deleted), rows folded into it become visible again, `view_content` stubs are cleared, and the compaction record gets `undone=true`. A rewind after the compaction keeps the summary. Checkpoint `msg_seq` values are unaffected (seqs never change).

Memory (`backend/memory`): one fact per file in `DOT_MEMORY_DIR` (default `~/.dot/memory`), frontmatter (`id, name, description, type`) + body, plus a regenerated `MEMORY.md` index. SQLite tables `memory_facts` and FTS5 `memory_fts` mirror the files for search; `reindex()` rebuilds them from the files at startup (hand-written files without an id get one written back; MEMORY.md is always regenerated). Vector search is off (`Embedder` protocol and `NullEmbedder` in `memory/services/embedder.py`, no dependency yet).
- `GET /v1/memory?q=&limit=` (q uses FTS), `POST /v1/memory` `{name, description?, kind?, body}` -> 201, `PUT /v1/memory/{id}` (partial), `DELETE /v1/memory/{id}` -> `{ok: true}`. kind: `user|feedback|project|reference`. Ids `M` + 9 chars.
- Tools (both deferred, load with ToolSearch): `Memory` (`action: add|update|delete|search|list`, mutating: needs approval in default mode, denied in plan mode) and `MemoryRecall` (`search|list`, read-only). Recall and search output with at least one fact is marked tainted (facts are model-written and may repeat web text), so in auto mode later mutating calls escalate like after any untrusted tool result.
- `consolidate(service, llm)` (`memory/services/consolidate.py`): exact-duplicate removal plus LLM merge of near-duplicates; an async function for a later scheduler.
- New codes: 2020 compaction failed (502), 2021 memory fact not found (404), 2022 invalid memory fact / store full (400).
- `LLMClient.complete(messages, max_tokens)` is the non-streaming helper (4000 on failure); `ScriptedLLM(scripts, completions)` doubles it, `realistic_usage=True` makes it report prompt sizes.

## Phase 5: web tools
- `GET /v1/tools` -> `[ToolInfo {name, description, deferred, mutating, source: builtin|mcp, input_schema}]` for every registered tool (core and deferred), in registry order.
- Core (in the static prefix, `mutating=false`, results `tainted`): `WebSearch(query, max_results=8 (cap 20), categories?, time_range?: day|week|month|year, allowed_domains?, blocked_domains?)` returns numbered `title / url / snippet [engines]` lines from the internal SearXNG (`DOT_SEARXNG_URL`, default `http://dot-searxng:8080`; on a host dev run use the published port). Titles and snippets are one-lined, length-capped and stripped of control tags. Queries are not logged (the httpx request log is raised to WARNING).
- `WebFetch(url, prompt?)`: backend-side SSRF guard in `backend/core/ssrf.py`. Only http(s); no credentials in the URL; localhost / `.local` / `.internal` / single-label names, loopback, link-local (incl. cloud metadata), private, CGNAT, multicast, reserved and IPv4-mapped / NAT64 / 6to4 IPv6 addresses are refused, as are decimal, hex, octal and short IPv4 forms. DNS is resolved once per hop, every answer must be public, and the connection goes to the vetted IP with the original `Host` header and TLS SNI (no rebinding window). Redirects are followed manually (max 5), each hop re-vetted. Limits: 2 MB on the wire and after decompression (gzip/deflate only, bounded inflate), 15 s per request / 30 s total, content types `text/*`, json, xml, xhtml (PDF and other binaries are refused with 4014). HTML goes through trafilatura to markdown; output is cut at 20000 chars with a note. Cache: 15 min, 64 entries, keyed by URL. `prompt` is echoed, not sent to any model. `DOT_WEB_UNSAFE_ALLOW_LOOPBACK` (default false) is for tests only.
- Deferred (activate with `ToolSearch`), all results tainted: `BrowserNavigate(url | back=true)` and `BrowserRead(view: snapshot|extract|screenshot|scroll_down|scroll_up|scroll_top|scroll_bottom, selector?, full_page?)` are `mutating=false`; `BrowserClick(element_id, select_value?)` and `BrowserType(element_id, text, submit?)` are `mutating=true`. They call the browser worker (`DOT_BROWSER_URL`, default `http://dot-browser:8091`, `DOT_BROWSER_TOKEN`) with `X-Session-Id` = the tool's session id (a subagent uses its own `<parent>-sub-<n>`). Screenshots are not stored (no binary file endpoint in the sandbox): the result only reports mime and size. A stopped worker gives error 4015.
- Rules: `WebFetch(domain:example.com)` (also `BrowserNavigate(...)`) matches the host and its subdomains, ignoring case, a trailing dot and padding around the URL. No baseline allow rule is shipped for WebSearch/WebFetch: both are read-only and already allowed by default, and a bare allow would shadow a user's `ask WebFetch(domain:...)` (precedence deny > allow > ask).
- Subagents: Explore, Plan and general-purpose get WebSearch/WebFetch; general-purpose also gets the four Browser tools preloaded (a child has no ToolSearch); Verifier gets no web tools. A child that read web content reports `tainted`, and its parent then escalates mutating calls in auto mode.
- New codes: 4010 search unavailable (502), 4011 invalid search response (502), 4012 URL not allowed (403), 4013 fetch failed (502), 4014 unsupported or oversized content (415), 4015 browser unavailable (502), 4016 browser action failed (502). Tools return them as `is_error` results (`<Tool> failed (error N): ...`), not as stream errors.

## Phase 5: MCP client, scheduler, compose
### MCP (`backend/mcp`)
- Config: `mcpServers` in `~/.dot/settings.json` (user scope) and `<workspace>/.dot/settings.json` (project scope; wins on a name clash). Entry: stdio `{command, args, env, cwd}` or remote `{type: "http"|"sse", url, headers, allowHosts}`; `disabled: true` keeps it off. Names match `[A-Za-z0-9_.-]{1,40}`. A bad entry makes the settings file invalid (3005, fail closed).
- Trust: project-scope servers are never launched before the user approves them. Approval is stored in `mcp_trust` keyed by (name, sha256 of the config); any config change needs a new approval. User-scope servers are trusted. Approvals write an audit row (`session=mcp`, `tool=mcp_trust`, `source=user`).
- `GET /v1/mcp/servers` -> `[{name, transport: stdio|http|sse, scope: user|project, status: connecting|connected|failed|needs_trust|stopped, tool_count, trusted, error}]`; `POST /v1/mcp/servers/{name}/reconnect` and `.../trust` -> one entry (4030 unknown name). MCP never affects `/ready`. Settings edits are picked up within `DOT_MCP_RECONCILE_INTERVAL_S` (5 s).
- Transports: stdio servers run INSIDE the sandbox (spec 4.3). The backend drives them through `POST /internal/mcp/spawn {command,args,env,cwd}` -> `{proc_id}`, `/internal/mcp/{id}/send {line}`, `/internal/mcp/{id}/recv {timeout_s<=25}` (long poll -> `{lines, alive, stderr}`) and `/internal/mcp/{id}/close`. Env = the sandbox's scrubbed allowlist + the explicit `env` of the config (`LD_*`, `BASH_ENV`, ... refused), cwd jailed to the workspace, own process group killed on close, max 8 processes (`max_mcp_servers`), 4 MB per message, 16 MB unread-output cap. Long polling (not websockets) keeps it testable over the in-process ASGI transport. HTTP/SSE: URL and every request host go through `core/ssrf.vet` unless the host is in `allowHosts`; redirects are re-vetted per hop. The request is rewritten to the vetted IP (Host header and TLS SNI keep the real name), so there is no second DNS lookup (no rebinding window); `trust_env=false` ignores proxy env vars. Use `allowHosts` only for hosts you control (no pinning there). Spawned processes belong to the spawning `X-Session-Id` (other sessions get 404) and are killed when the backend stops polling for 120 s; a `recv` answer is capped at 200 lines / 8 MB.
- Secrets: `${NAME}` in `env` and `headers` values expands only names listed in `DOT_MCP_ENV_ALLOWLIST` (comma list, backend env), once, no recursion; anything else or an unset name makes the server `failed`. Remote OAuth browser flow is NOT implemented (follow-up): use bearer headers from allowlisted env vars.
- Tools: `mcp__<server>__<tool>`, characters outside `[a-zA-Z0-9_]` become `_`, 64 chars max, collisions get `_2`, `_3`. All are `deferred` (found with ToolSearch). Descriptions are untrusted: control tags stripped, one line, 300 chars (120 per property); schemas keep only a llama-grammar-safe subset (no `$schema`, `pattern`, `format`, `default`, `patternProperties`, `if/then`, remote `$ref`; local `$ref`/`allOf` inlined; depth 6, 40 properties, 8000 chars, else a free-form object). Max `DOT_MCP_MAX_TOOLS_PER_SERVER` (50) tools per server; `tools/list_changed` re-lists.
- Governance: server hints are untrusted claims and never auto-allow. Every MCP tool has `needs_approval=true`: the user is asked in every mode except bypass (never the classifier, even in auto) unless an explicit allow rule matches. `readOnlyHint=true` (without `destructiveHint`) only gives `mutating=false`; plan mode denies mutating ones. Server sampling, roots and elicitation requests are refused. Property names and enum/const strings of tool schemas are sanitised (names must match `[A-Za-z0-9_.$@-]{1,64}`). Rules (`mcp__server__*` globs), PreToolUse hooks and plan mode apply to every MCP tool regardless of hints. Output is ALWAYS `tainted`, including errors; text over 12000 chars is head/tail clipped and the whole text (<=5 MB) is spilled to `.dot/tool_outputs` via `POST /internal/spill`. Per-call timeout `DOT_MCP_CALL_TIMEOUT_S` (60). Image/audio blocks are replaced by a size note; resources and prompts are out of scope.
- Reconnect: backoff 1, 2, 5, 10, 30 s, then it waits for `POST .../reconnect`; a failed ping (every 30 s) or a closed stream also reconnects. Tools disappear while a server is down. `SkillRegistry.set_environment(tools, connected_servers)` is refreshed on every change (`requires: mcp:` works). `Runtime.close` stops every connection and kills the sandbox processes.
- New codes: 4030 server not found (404), 4031 not trusted (403, reserved), 4032 connection failed (502, reserved), 4033 call timed out (504, reserved), 4034 URL not allowed (400, reserved), 4039 config invalid (400, reserved). Tool-side failures are `is_error` results.

### Scheduler (`backend/scheduler`)
- In-process asyncio loop (no Celery), SQLite tables `scheduled_jobs` (id `J`+9) and `scheduled_job_runs` (last 50 per job kept). Cron: 5 fields, `*`, lists, ranges, steps, month/weekday names, `@hourly|@daily|@weekly|@monthly|@yearly`, evaluated in `DOT_TIMEZONE`; dom and dow are ORed when both are restricted. DST: a time skipped by spring-forward fires once, shifted forward; a repeated time fires once (first occurrence). Own parser, no `croniter` dependency.
- `GET /v1/schedules`, `GET /v1/schedules/{id}`, `POST /v1/schedules {cron, prompt, enabled=true}` -> 201, `DELETE /v1/schedules/{id}` -> `{ok}`. `ScheduleInfo {id, kind: user|builtin, cron, prompt, enabled, created_at, last_run_at, next_run_at, last_status, runs[{started_at, finished_at, status: ok|failed|missed|running, session_id, detail}]}`. Codes: 4035 invalid cron (400), 4036 not found (404), 4037 job cap `DOT_SCHEDULE_MAX_JOBS` (409), 4038 built-in cannot be deleted (409).
- Tools (deferred): `CronCreate(cron, prompt, enabled?)` and `CronDelete(id)` are mutating and `needs_approval` (asked in every mode except bypass, never the classifier), `CronList` is read-only (output tainted while user jobs exist).
- Runs: concurrency 1; the next slot is persisted before the run starts (a crash cannot double fire; runs open at startup are marked failed `interrupted by a restart`); a fresh session per run (title `[scheduled] ...`), headless through the normal engine with mode `DOT_SCHEDULE_MODE` (default `default`; `bypass` or unknown values are coerced to `default`). A call that needs approval waits `DOT_APPROVAL_TIMEOUT_S`, then the run fails (`error 3001`); a user can approve it through `/v1/approvals` meanwhile. Run limit `DOT_SCHEDULE_RUN_TIMEOUT_S`. Jitter 0..`DOT_SCHEDULE_JITTER_S` is added to every next run. Missed runs (more than `DOT_SCHEDULE_MISSED_GRACE_S` late, e.g. after downtime) are skipped, logged and recorded as `missed`, never replayed.
- Built-ins (rows with `kind=builtin`, created at startup, not deletable): `builtin:memory` 03:30 daily (`memory.consolidate`), `builtin:retention` 04:15 daily (`POST /internal/retention`), `builtin:logs` Sunday 04:45 (run-history older than 30 days).
- Sandbox `POST /internal/retention {checkpoint_days=14, checkpoint_max_bytes=50000000, outputs_days=7}` -> `{checkpoints_removed, outputs_removed, bytes_freed}`: checkpoints older than N days are removed, then the oldest of a session until it fits the byte cap; spill files in `.dot/tool_outputs` expire. Optional `protect_sessions: [id]`, `protect_last` (default 50): the newest N checkpoints of those sessions survive age and size rules (the backend passes sessions with a checkpoint in the last 24 h). Symlinked `.dot/checkpoints` or `.dot/tool_outputs` entries are never followed; prune and restore are mutually exclusive. Pruned checkpoint ids are never reused (`.max` marker). Rewinding past a pruned checkpoint fails with 3004.

### Compose
- Services: `dot-searxng` (pinned `searxng/searxng:2026.11.17-b99cf7496`, internal only), `dot-browser` (profile `browser`, `make up-browser`, needs `DOT_BROWSER_TOKEN`), `dot-web` (127.0.0.1:3000). Networks: `dot-internal` (llm, sandbox, backend, searxng, web), `dot-browser-link` (internal, backend <-> browser only), `dot-browsing` (browser egress). Only 127.0.0.1 ports are published (llm 8080, sandbox 8090, backend 8000, browser 8091, web 3000).
- Docker cannot block LAN egress by itself: `deploy/scripts/firewall_browser.sh` prints DOCKER-USER iptables rules that drop the browser subnet's traffic to private, link-local and loopback ranges (`--apply` / `--remove` need root; it is never run by make). The backend is reachable from the browser over `dot-browser-link` (bearer token still required).

## Hardening
- `/health` is liveness only (200 `{"status":"ok"}`, touches nothing, no auth). `/ready` is readiness (no auth): 200 `{"status":"ready"}` only when the SQLite database answers `SELECT 1` and both the sandbox `/health` and the llama-server `/health` answer; otherwise 503 code 1008 with `Retry-After: 5` (the log line names which dependency failed). The browser worker, SearXNG and MCP servers never affect `/ready`. Compose healthchecks use `/health`; use `/ready` to know whether chat can work.
- Startup: an invalid configuration (missing or placeholder `DOT_API_TOKEN`, unwritable `DOT_DB_PATH` or `DOT_MEMORY_DIR`, `DOT_WORKSPACE` not a directory, missing permissions/rules file, unknown `DOT_TIMEZONE`, non-numeric limits) prints every problem as one line on stderr plus a JSON line and exits with status 2, no traceback. Secret values are never printed.
- Limits: `POST /v1/sessions/{id}/chat` rejects a message longer than `DOT_MAX_MESSAGE_CHARS` (default 100000) with 413 code 1010. Any request body over `DOT_MAX_BODY_BYTES` (default 1048576; checked by `Content-Length` and again while streaming) gets 413 code 1011. Both are checked after authentication for the message limit; the body limit applies to every route.
- Rate limit: chat starts are limited per client address by an in-memory token bucket, `DOT_CHAT_RATE_PER_MIN` tokens per minute (default 30) with a burst of `DOT_CHAT_RATE_BURST` (default 10). Over the limit: 429 code 1004 with `Retry-After` (seconds). Only authenticated requests spend tokens; scheduled runs do not go through HTTP and are not limited. The state is lost on restart.
- Headers on every response: `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, `Content-Security-Policy: default-src 'none'; frame-ancestors 'none'` (not on the dev-only `/docs`), `Cache-Control: no-store` on `/v1/*` unless the route sets its own (SSE uses `no-cache`). There is no CORS: no `Access-Control-*` header is ever sent, browsers reach the API only through the web-ui server.
- The API token is compared with `secrets.compare_digest`; configured tokens and `Bearer ...` values are masked in every log line.
- Shutdown: on SIGTERM the lifespan cancels running turns (they end as `cancelled`), then stops the scheduler and MCP connections, closes the HTTP clients and disposes the database.
- New codes: 1010 message too long (413), 1011 body too large (413). 1004 (429) is now used by the chat rate limit.
